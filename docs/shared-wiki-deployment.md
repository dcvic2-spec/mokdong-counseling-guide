# 목동 상담부 공동 업무 위키 — 배포 가이드

> 이 저장소는 공개(Public)입니다. 학생·학부모 정보, 내부 운영 매뉴얼 원문, Google Sheets ID, Google Drive 폴더 ID, 계정 정보 및 비밀번호를 이 저장소에 커밋하지 마세요.

## 구성
- **Google Sheets**: 업무 위키 문서, 수정 이력, 주간 체크리스트의 공동 데이터베이스
- **Google Apps Script**: 문서 로드·저장, 버전 충돌 감지, 사진 업로드와 주간 체크 기록
- **HTML Service**: 직원이 사용하는 파란색 나무위키형 편집 화면
- **GitHub**: 비밀정보 없는 소스 코드 설명과 설치 문서만 보관

GitHub Pages는 이 구조에서 **실제 업무 위키를 호스팅하지 않습니다.** 직원들은 Apps Script 웹앱 URL로 접속합니다.

## 1. 소유자 계정에서 Apps Script 만들기
1. 구글 드라이브에서 **목동 상담부 공동 업무 위키 DB** 스프레드시트를 엽니다.
2. **확장 프로그램 → Apps Script**를 누릅니다.
3. 설치 패키지의 `Code.gs` 내용을 새 Apps Script 프로젝트의 `Code.gs`에 붙여넣습니다.
4. 왼쪽 **+ → HTML**을 선택하고 파일명을 정확히 **Index**로 작성합니다. 설치 패키지의 `Index.html` 코드를 붙여넣습니다.
5. `Code.gs`의 `WIKI_DB_ID`와 `WIKI_FOLDER_ID`가 연결하려는 실제 비공개 자료를 가리키는지 확인합니다. **이 식별자가 들어간 실제 코드를 공개 GitHub에 푸시하지 마세요.**
6. 저장(Ctrl+S)합니다.

## 2. 접근권한 설정 — 중요
- **개인 Gmail 계정에서 '나로 실행(Execute as me)' + '모든 사용자(Anyone)'를 동시에 선택하지 마세요.** 문서 읽기/쓰기 API가 외부에 노출될 수 있습니다.
- 운영 전에는 **'웹앱에 액세스하는 사용자로 실행(Execute as user accessing)'**을 우선 검토하세요. 각 직원에게 스프레드시트 및 위키 사진 폴더에 필요한 최소한의 권한을 부여해야 합니다.
- Google Workspace 도메인이 있는 경우 조직 내부 접근만 허용하는 설정을 우선 사용하세요.
- 개인 Gmail만 쓰는 경우 Apps Script 배포 UI에서 특정 이메일만 선택하도록 제한할 수 없을 수 있습니다. 신뢰 가능한 구글 계정만 데이터베이스에 공유하고, 실제 직원 계정으로 권한 차단 테스트를 수행하세요.
- 소유자의 계정과 별도의 **권한 없는 계정**으로 문서가 열리거나 API 호출이 성공하지 않는지 반드시 확인해야 합니다. 검증 전 실제 개인정보를 입력하지 마세요.

## 3. 웹 앱 배포
1. Apps Script 편집기 오른쪽 상단 **배포 → 새 배포**.
2. 유형 선택(톱니바퀴)에서 **웹 앱** 선택.
3. 설명은 `목동 상담부 공동 업무 위키 v1`로 작성.
4. 실행 사용자와 액세스 대상을 위 **접근권한 설정** 기준에 맞게 선택.
5. **배포** → 필요한 Google 권한을 검토하고 승인.
6. 표시되는 `.../exec` 웹앱 URL을 복사합니다.
7. 직원 한 명과 함께 접근·수정·사진 첨부·반영을 시험합니다.

## 4. 공동 편집 시험
1. 직원 A와 직원 B가 **동일한 웹앱 URL**을 각자의 브라우저에서 엽니다.
2. 직원 A가 '데일리 업무' 문서에 테스트 문장을 추가하고 **저장 및 공유**를 누릅니다.
3. 직원 B의 화면에 변경된 문서가 약 15초 후 나타나는지 확인합니다.
4. 두 직원이 같은 문서를 동시에 편집하여 버전 충돌 경고가 나오는지 확인합니다.
5. 사진을 첨부하고 저장한 후 다시 열어 이미지가 표시되는지 확인합니다.
6. **주간 업무 체크리스트**의 금요일 'Weekly Notice 알림장 발송' 및 '발송 결과 확인'을 시험합니다.
7. 테스트용 문장을 삭제하고 수정 이력에서 변경 내역을 점검합니다.

## 5. 변경·유지관리
- HTML이나 서버 코드를 변경하면 Apps Script에서 저장한 뒤 **배포 → 배포 관리 → 수정 → 새 버전 → 배포**를 통해 기존 웹앱 URL을 유지하면서 갱신합니다.
- 공동 데이터 변경은 앱에서 수행하는 것이 원칙입니다. 스프레드시트의 문서 본문·버전을 직접 수정하면 충돌 감지와 수정 이력이 손상될 수 있습니다.
- 주기적으로 문서·이력 시트를 백업하고, Google Drive 파일 공유 범위를 점검합니다.
- 직원이 퇴사하면 스프레드시트, 이미지 폴더 및 Apps Script 관련 공유 권한을 회수합니다.

## 6. 아직 확인되지 않은 부분
현재 코드와 데이터베이스는 준비되어 있으나 **소유자 계정에서 웹앱을 배포하고 실계정 간 공동 편집을 검증하지는 않았습니다**. 따라서 배포·접근제어·이미지 기능을 실제 운영 완료로 간주하지 마세요.
